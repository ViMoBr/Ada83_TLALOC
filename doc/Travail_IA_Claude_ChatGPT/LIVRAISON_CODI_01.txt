LIVRAISON CODI-01 — les trois codi : O_TRUNC sur SYS_FILE_CREATE
=======================================================================

CONTEXTE : temoin trunc_test en ECHEC (lignes fossiles apres une
re-creation plus courte) — CREATE Ada n'ecrase pas la queue d'un
fichier existant. Cause : flags d'ouverture codes en dur dans la
macro SYS_FILE_CREATE des trois codi : 0x42 (O_CREAT|O_RDWR), sans
O_TRUNC (0x200). Semantique Ada de CREATE = fichier NEUF : la
troncature est requise. Revele par le byte-diff TC-05 (330 octets
exacts ecrits, 375 sur disque — le fantome etait dans le systeme de
fichiers, tous les invariants internes de TARGET_CODE avaient
raison).

REMEDE : flags 0x42 -> 0x242, soit UN immediat par cible :
  x86    : mov esi, 0x242            (octet poids-faible+1 : 00->02)
  ARM64  : movz x2, #0x242  = 0xD2804842   (imm16<<5 : 0x242*32)
  RISC-V : addi a2, x0, 0x242 = 0x24200613 (imm12<<20 ; 578 < 2047 ok)
SYS_FILE_OPEN (O_RDWR seul) inchange — l'ouverture d'un existant ne
tronque pas, c'est CREATE seul qui change.

PORTEE : le codi n'apparait pas dans les FINC — le POINT FIXE DES
FINC EST INTOUCHE ; seuls les binaires assembles changent (5 octets
x86, 4 ARM, 4 RISC-V). MIROIR TARGET_CODE : quand SYS_FILE_CREATE
entrera dans la table EMITS, l'immediat sera 0x242 — les deux
assembleurs restent synchrones par construction.

COMMIT 1 — "codi x3 : O_TRUNC sur SYS_FILE_CREATE (semantique Ada de
            CREATE) ; temoin trunc_test"

ORACLE DU COMMIT :
  1) trunc_test (reassemble avec le codi corrige) : "PASSE
     trunc_test" ;
  2) filet fichiers : direct_io, sequential_io toujours verts ;
  3) point fixe : diff des 63 FINC VIDE (le codi n'y figure pas) ;
     T2 reassemble fonctionne a l'identique ;
  4) ARM : cross-assembler un temoin trunc et le rejouer sur Orange
     Pi quand l'occasion se presente ; RISC-V : en attente VisionFive
     (meme reserve que d'habitude).
